# APP 更新与在线配置

Android 0.3.6（versionCode 9）加入版本检测。已有旧版用户先安装本次发布包，后续版本由 APP 检测并提示更新。正式包名和发布证书固定沿用。

登录后台进入「版本发布」，配置版本名称、数字版本号、更新说明和安装包。发布开关控制更新提示；最低支持版本为 0 时允许稍后更新，低于配置的最低版本需升级后继续使用。版本比较使用 versionCode，当前版和更高版本不提示降级。

「大厅公告」保存后由前台客户端定期读取，也会在回到前台时刷新。红包雨、奖励阶梯和大厅推送规则继续使用服务端已有配置。原生界面、业务代码和广告 SDK 更新通过签名 APK 安装。

APP 在隐私同意后检查版本，设置中提供手动检查。更新下载到应用缓存，安装前核验文件大小、SHA256、包名、版本号和当前签名，再交给系统安装。Android 安装权限由用户在系统页面授权。

发布时使用带版本号的固定下载地址，保留已发布安装包。首页通用下载地址继续指向最新版。生成交付文件示例：

```powershell
python tools/package-investigation.py 0.3.6 9 0.5.0 '新增版本检查、在线更新和大厅公告'
```

输出的 `output/小橙有喜-0.3.6-更新发布.json` 可在后台导入，再保存发布；其中包含版本、下载地址、文件大小和 SHA256。JSON 是发布草稿，导入后由管理员确认保存。

后续每次更新先判断发布方式。公告、奖励、红包雨与推送参数使用在线配置；网页和服务端修改按各自范围部署。原生小修逐次评估代码热补丁的适用性与接入成本，界面、权限、SDK 变更走签名 APK。当前已提供在线配置刷新和 APK 升级，代码热补丁机制在具体改动需要时实现。

每次 APK 发布沿用同一流程：递增实际版本、核对 APK 包名/版本/固定签名，明确填写更新说明，生成本次发布 JSON；上传对应版本文件并同步通用下载入口，保存后台版本检测配置，最后用同一 JSON 验收公网。已有版本地址保留原文件；默认可选更新，必要升级按本次兼容要求设置最低支持版本。

部署脚本从本次 JSON 读取安装包文件名。公网验收接收本次文件，自动检查新旧版本及最低支持版本边界：

```powershell
python tools/verify-app-updates-live.py 'output/小橙有喜-0.3.6-更新发布.json'
```

`GET /api/app/update?version_code=N` 提供公开版本检查，`GET /api/app/runtime` 提供大厅公告。配置保存在 SQLite，管理端保存与操作审计同一事务提交。本次部署通过 `deploy/upgrade-app-updates.sh` 安装，部署发布记录使用 `deployment` 主体，管理员账号以现有数据库为准。

验证完成：Debug/Release 构建、固定证书核验、3 项后端针对测试、后台及公告浏览器 mock 交互、公网新旧版本判断、受保护管理接口、no-store 响应和完整 APK 下载 SHA256。线上已发布 0.3.6，revision 2，最低支持版本 0。公网验收输出为 `output/app-updates-live-verification.json`；设备系统安装流程尚未实测。
